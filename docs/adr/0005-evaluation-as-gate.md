# 0005 — Evaluation as a merge gate: the synthetic deck, the contradiction set, two tiers, the metrics and their bars

- **Status:** proposed
- **Date:** 2026-10-16
- **Issue:** #5

## Context

cram.ai is a self-hosted tutor that turns one student's lecture slides into cited answers, revision notes and practice exams, and each guarantee it makes about that text holds only as long as something checks it on every change.

This decision is argued from [CLAUDE.md § Hard constraints](../../CLAUDE.md#hard-constraints), which it cites and does not restate. It answers three of those bullets: the one headed "The slides win", whose contradiction-set bar this ADR turns into a merge gate; the bullet on real course material, which bounds what the eval deck may be; and the one headed "Nothing the tutor says is uncited", which is what citation validity measures.

The command surface is [CLAUDE.md § Commands](../../CLAUDE.md#commands)'s. It owns the names `pnpm eval` and `check:eval-report`, the fact that CI cannot run a local model, and the categories of change that owe an eval report. This ADR decides what those names mean.

The hard case is the subject class `docs/adr/0001-grounding-architecture.md` § Context names; an eval that does not exercise that class on purpose measures only the easy case.

Issue #3's target-machine comment describes the machine the student runs: a CPU-only laptop, on which a model-in-the-loop run over a whole deck is slow.

The eval deck is authored as text because `.claude/scripts/check-no-course-content.sh` (#17) refuses tracked slide binaries. #31 is open on how ingest adapter tests get binary inputs, and this ADR decides nothing #31 owns.

What exists: the domain schemas in `packages/shared/src/` (#8) — `unit.ts` (`Unit`, `UnitKind`), `citation.ts` (`Citation`, `SourceId`), `verification.ts` (`Verdict`, `WithheldReason`, `PartialPolicy`) and `slide-record.ts` (`SlideRecord`, `LectureId`, `SlideNo`). What is pending, and whose: the fake gateway (#12), the grounding pipeline (#13), the deck and its golden questions (#14), and the runner and its gate, which belong to `docs/plan.md` §8 M2 and a ticket of their own.

Two standing documents deferred to this ADR: `docs/adr/0001-grounding-architecture.md` § Decision (f) and `docs/standards/grounding.md` rule 8 each say that how the contradiction set gates a merge is ADR 0005's.

## Decision

- **(a) The eval course.** It lives under `eval/decks/`: self-authored, a fictional subject, tracked as text. It is synthetic under the `CLAUDE.md` bullet cited above, so recordings of model output over it are free to commit too. It has four required properties, each a category whose size is the deck's author's to choose (#14): facts spread across lectures, so notes must synthesise; near-duplicate concepts, so retrieval must discriminate; slides whose text exists only as an image in any rendered form, with the true text held in the source, so derived-text quality is measurable — the metric over them is ADR 0006's (#6) to define, and whether any rendering is tracked is #31's; and a contradiction set, defined in (b). Every eval contract is defined over `SlideRecord` (`packages/shared/src/slide-record.ts`), so no tier depends on a binary rendering.
- **(b) The contradiction set, defined.** Each item is a slide asserting a claim a general model holds false, paired with a golden question whose `expectedCitations` name that slide and whose `mustNotContain` names the general-knowledge claim and its caveat phrasings. The set also holds questions the deck does not cover at all, with empty `expectedCitations`, whose expected result is the not-covered result of `docs/standards/grounding.md` rule 5. A surviving unit is one that reaches the student after resolution and verification. An item passes when at least one surviving unit cites an expected slide — or, for an uncovered item, no unit survives and the not-covered result is returned — and no surviving unit's text contains any `mustNotContain` entry. The withheld panel (`docs/standards/grounding.md` rule 7) is exempt from `mustNotContain`: a withheld sentence on show is the mechanism working. The contradiction set's bar is the one `CLAUDE.md` § Hard constraints sets, cited by section and carrying no figure, in the form `docs/adr/0001-grounding-architecture.md` § Decision (f) uses.
- **(c) Golden questions.** `eval/questions.jsonl` holds one JSON object per line, with its fields fixed here. `question` is the text asked. `expectedCitations` names each expected slide by `lectureId` and `slideNo` (`LectureId` and `SlideNo` in `packages/shared/src/slide-record.ts`), never by a minted `SourceId`, because `packages/shared/src/citation.ts` leaves minting to ingest and the index (#10, #11) and the deck must stay stable across both. `mustNotContain` entries are matched as case-insensitive, whitespace-normalised substrings of surviving units' text, never as regexes, so a fixture stays readable. The draft's `expectedAnswerUnits` (`docs/plan.md` §4 as it stood before this ADR) is not adopted: no metric in (d) reads it, and a field nothing reads is a fixture that rots; a metric that needs it adds it by amendment. The schema is defined once, in `eval/` (#14 writes it), and both tiers validate against it.
- **(d) The metrics**, each defined by its numerator and denominator, with the tier that measures it and its bar. The four whose bar is a baseline are the ratio metrics, and "baseline" is (f)'s rule.

- **(e) Two tiers.** Tier 1 is deterministic and runs under `pnpm test`, so `verify:full` and CI inherit it (`CLAUDE.md` § Commands). It replays recorded model outputs through #12's fake gateway and proves the pipeline's mechanics: resolution and withholding, `mustNotContain` filtering of a fixed model output, rubric and grading arithmetic, and the stored-exam invariant of (d). A recording is keyed by the full request content — role, model pin and prompt text — and **a miss is a failure, never a fallback**: a recording keyed by less replays yesterday's model against today's prompt and proves nothing. Recordings are produced by the runner from a tier-2 run and committed under `eval/recordings/`. `eval/` becomes a workspace member (`pnpm-workspace.yaml`) when the first ticket needs it (#14); it depends on `packages/*` and nothing depends on it, the direction `docs/standards/architecture.md` rule 1 sets. Tier 2 is `pnpm eval`: local, the real backend through the gateway, the whole pipeline over the deck, writing the report in (f). It uses the backend's deterministic settings where the backend offers them, and the report records them; nondeterminism is a reason to re-run, never a reason to lower a bar that admits no failure.
- **(f) The report.** It is committed under `eval/reports/`, named by the short SHA of the tree it measured. Its floor: the measured commit; the model pin per role, as ADR 0003 names them; the machine class; the determinism settings; every metric in (d) with its bar or baseline; and the per-item failures for citation validity and the contradiction-set pass rate, so that a red is diagnosable. The newest report on `main` is the baseline. Citation validity and the contradiction-set pass rate are red on any failure, whatever the baseline. A ratio metric below its baseline is a regression that the PR body argues and the review decides; correctness bugs block merge (`CLAUDE.md` § Workflow).
- **(g) `check:eval-report`'s shape.** A `verify:full` leg, since every gate joins it (`CLAUDE.md` § Commands), red when the branch's diff against `main` touches any trigger path and does not add or update a file under `eval/reports/`. The trigger path set has one owner, the script, and covers the categories `CLAUDE.md` § Commands names, each mapped to its owner: prompts to `packages/grounding` (#13, where prompts live and nowhere else), retrieval to `packages/index` (#11), the gateway to `packages/gateway` (#12), and model config to wherever ADR 0003 places it. An owner that moves takes its new path into the set in the same change. The gate is a floor, not a proof: it sees a report's presence, and the review sees its freshness and content — the split `.claude/workflow.json` → `mergeRitualGate` records for its own gate. Which `.claude/scripts/verify-tier.sh` rungs run it is that script's docblock's to argue when the gate lands.
- **(h) What each ticket delivers.** This ADR delivers the decision. #14 delivers the deck, `eval/questions.jsonl`, the hand labels and (c)'s schema. #12 delivers the fake gateway with (e)'s keying and miss rule. #13 delivers the pipeline the metrics run over. A new ticket under `docs/plan.md` §8 M2 delivers the runner, the recordings, the reports and the gate. ADR 0003 delivers the pins a report names, and ADR 0006 the derived-text metric.
- **(i) Sequencing.** M2 lands before notes and exams (`docs/plan.md` §8), so every later feature lands with its metric and its golden questions.
- **(j) Who owns which figure.** This ADR owns the citation-validity bar; `CLAUDE.md` § Hard constraints owns the contradiction-set bar; every ratio metric has a baseline, not a number, until the first measured run records one.

## Options considered

**1. A dashboard** — metrics tracked per run, nothing blocked by them. Cheapest to build and never in the way. Rejected: a number nobody is blocked by rots, and two of the metrics are hard constraints, not indicators to watch.

**2. Model-in-the-loop in CI.** It would measure every PR with no local step. Rejected: CI cannot run a local model (`CLAUDE.md` § Commands); a hosted model would measure a model the student never runs; and the measured model must be the one on the target machine class (#3).

**3. One tier, all model-in-the-loop, run locally.** One harness, and every number is a real model's. Rejected: the pure core's guarantees (`docs/standards/architecture.md` rule 3) would be proven only when someone runs the slow thing, and CI would prove nothing about resolution.

**4. Two tiers, recorded replay, and a presence-floor gate in `verify:full` (chosen).** Its downsides are genuine and accepted:

- Recordings go stale on every prompt change and must be re-recorded; by design a miss is red, so a prompt change costs a tier-2 run before tier 1 is green again.
- A presence floor is satisfied by a stale report, so freshness is the review's to check.
- Reports are comparable only when their pins and machine class match, which is why a report carries both.
- `pnpm eval` on the target laptop is slow.
- The baseline rule has no mechanical comparator until two reports exist.

**5. The gate as a CI-only job reading the PR's file list** — the shape `docs/plan.md` §4 drafted. It needs nothing beyond the PR's metadata. Rejected for the `verify:full` leg: the author learns locally before pushing, and every caller inherits the gate. The cost is that the leg needs a merge-base with `main` wherever it runs, which the runner ticket provides.

## Consequences

**Easier.** Every feature lands with its metric. CI proves the pipeline's mechanics on every PR. A prompt change cannot merge unmeasured. The subject-class claim has a regression test with a mechanical pass condition.

**Harder.** Recording churn on every prompt change. Slow local runs. A report per trigger PR. Hand labels and hand marks are authoring work that grows with the deck.

**Explicitly accepted.** No ratio metric gets an invented threshold. The gate is a floor. `expectedAnswerUnits` is dropped. The uncovered-item pass condition lives inside the contradiction set rather than as a metric of its own.

**What would make us revisit.** A mechanical baseline comparator, once two reports exist. A deck too small to separate signal from noise on the ratio metrics. A second machine class that makes reports incomparable. A verifier so `partial`-heavy that precision and recall as defined stop being informative.
