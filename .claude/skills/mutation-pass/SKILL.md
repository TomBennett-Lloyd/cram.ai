Moved out of `.claude/agents/ticket-agent.md` rule 4 by #628, which keeps the obligation and a pointer from the `Mutation:` report line; this file owns the procedure and, since #669, the line's multi-line form (section 5). Citations of the form `cumulo#<n>` are the issues and PRs where each rule was earned there; bare `#<n>` is this repo's.

**Who does what.** The lane writes sections 1 to 3 inline, because a list is only worth having if it came from a source other than the lane's own guards. The lane commits first (`git status` clean), writes the lists to `<scratchpad>/mutation-<n>.md`, then dispatches one fresh synchronous `general-purpose` agent on Sonnet (`.claude/agents/ticket-agent.md` rule 3(f)) to run section 4 on that file. It keeps only the table that comes back, writes a case for each survivor, and runs section 4 again once, in a fresh agent, over the survivors alone. It then pastes the four lists into the `reviewer` dispatch and the PR body and names the two lists' sources and the corpus's oracle on the lane report's `Mutation:` line.

## 1. The edge list

**An edge list your own guards did not bound.** A list read off the guards you wrote holds only what you already believed; five tickets' review defects lay outside it (#188). So write two lists first, from sources you do not control. **(a) The input grammar:** every construct the parser, schema or spec accepts, enumerated from that schema or spec rather than from your code, each an input shape some case must reach — PR #83's rethrow arm, reached only by a broken page tree; PR #160's seven operand sites beyond the three the lane had reasoned about; PR #235's plan-row regex, written from the one scan shape its probe printed. Each construct also names every axis it can vary on — its position in the enclosing string, its case, its nesting depth — because cases that hold one value on an axis cannot kill a mutant that pins the guard to it: PR #278's colours all sat at a string's start or end, and four anchoring mutants survived to review. **(b) The criteria:** each acceptance criterion in the plan comment and each invariant the issue states names a guard that must exist, so a missing guard shows as a criterion with no mutant — PR #90's rebuild that dropped slides whose lecture had no stored deck; PR #154's deck byte cap and the URL parse outside the request boundary. Then a guard is its edges: each alternation arm and character class of a regex, each anchor, each boundary value, each direction of a parity or mirror check, each refusal arm and tie-break. One mutant per edge, never one per sample you already hold: delete or widen each edge in turn, run the harness — whose verdict is the exit code (`docs/standards/evidence.md` form 6) — and give any edge whose mutant goes red nowhere a case before review sees it (`docs/standards/testing.md` rule 8 for the mutant loop). **Where the guard has an oracle (the next two paragraphs), a kill case asserts the oracle's verdict on its input, never the head's**, so kill a survivor with an input on which the oracle sides with the head. When the oracle agrees with the mutant on every input that kills it, the head is wrong there: file that survivor `discovered`, name it in the PR body and on the `Mutation:` line as **declared**, and write no case for it. Ranking the head against a mutant when both miss the oracle takes a distance, such as the boundaries each shares with the oracle, never exact equality, which credits the row to neither. PR #531's `0d4da90` pinned `male.™ Drones` as one claim to kill a `\p{S}` mutant that the oracle and the mutant both split, its exact-equality count could not show the head was the worse of the two, and review withdrew the case in `f7734c0` (#532). A survivor is **equivalent** only once a second input shape from list (a) also fails to kill it, and you name that shape — PR #128 recorded the `sizeOf` `0` floor as equivalent and the reviewer killed it with a second shape. A guard whose every mutant is equivalent has no killable mutant: name it and the reason no input reaches it — the dependency behaviour that makes it redundant, cited — in the PR body and on the `Mutation:` line, and keep it only where the plan or a cited source asks for it, never silently. PR #132's feed filter is the form: onnxruntime-node ignores feeds the model does not declare, and the PR body declared the survivor. PRs #58 and #61 each shipped guards no case protected, and the reviewer's own mutants found them at the cost of a cycle (#62); PRs #64 and #72 then mutated only the arms their existing samples named, and review found two and four survivors in the edges those samples never touched (#74).

## 2. The hostile corpus

**A guard whose job is to exclude inputs also faces a hostile corpus, judged by an oracle that is not the code under test.** Mutating edges exercises the inputs a guard has and never those it should have refused, so a missing exclusion has no edge to mutate: PR #271's paren counter killed every mutant and was still too broad for `${b%(*}`. Before the first `reviewer` dispatch, build the corpus from list (a)'s hostile end — near-misses, nested and escaped forms, and every input the plan sets aside as out of scope, since a set-aside is itself an exclusion (PR #313's pdf.js deletion of `<` and `>`, set aside without being checked against the inverse it can break) — and settle each verdict by the real interpreter or library run on the input, or by a recorded fixture. The previous version is not an oracle: diffing its verdicts against the new one's shows which changed, never which change is the fix; PR #289 settled each by running the command under `zsh -fc` with a stub `git` and reading whether the revert ran (#296).

## 3. The differential

**A change to a parser or guard that has a prior version on `main` runs a differential corpus before the first `reviewer` dispatch.** Generate the corpus from list (a) — every construct, each varied on its axes — rather than from the rows you wrote, and settle each row's verdict three ways: the oracle (the real interpreter or library, as above), the branch head, and `main`'s version of the guard. Report the count of rows where `main`'s verdict matches the oracle's and head's does not; it must be 0, and the `reviewer` dispatch and the PR body paste the corpus size and that count. **Rows the guard's contract departs from the oracle's on purpose are excused only by a named divergence**: a predicate stated once, with the spec clause it departs from and the case that pins the departure, as a committed test helper beside the differential or a named issue paragraph that states the predicate itself. A later lane cites it and never rewrites it, and a class already classified but recorded nowhere is recorded by the next lane that meets it. A predicate that reads the guard's own vocabulary, such as the mark run it strips, takes that vocabulary as a fixed input recorded beside it by commit, never from the candidate it classifies, because a widened mutant would otherwise widen the class that excuses it. Its positive control is a mutant that changes that vocabulary, classified with the fixed set, and it must leave a nonzero residual. Report the raw count and the residual after the named divergence; the residual must be 0. PR #506 (#444), PR #531 (#505) and PR #545 (#527) each rewrote `splitClaims`' numeral class row by row (UAX #29 SB8 joins across `.` and a numeral when a lowercase word follows, where a case pins `main`'s split) and reported its residual 0 in prose. PR #545's first predicate took its strip set from the candidate, and its control left residual 0 until review froze the set to the head's `MARK_RUN`, when it left 10,500 and 9,792 (#532). The previous version is still not the oracle — it is the third column, there so a regression shows as a row rather than as a review cycle. PR #394's three cycles found 9, then 1, then 25 such rows, each by a reviewer running this comparison; the confirmation pass that ended the loop ran it over 820 rows (#410).

## 4. The run (the dispatched agent)

You are read-only to the lane's worktree: never write there, and never commit.

1. Make a detached scratch copy at the lane's HEAD: `git worktree add --detach <scratchpad>/mut-<n> HEAD`, then `pnpm install --frozen-lockfile` inside it when any listed test needs dependencies (`.claude/agents/reviewer.md` states why the copy sits outside the lane's tree). Remove it at the end with `git worktree remove --force <scratchpad>/mut-<n>`.
2. For each mutant in the lists file, in the copy: apply the edit, run the named test file (`pnpm --filter <pkg> exec vitest run <file>`), read its exit code, revert by the inverse edit (`docs/standards/testing.md` rule 8; never `git restore` or `git checkout <path>`), and confirm the copy is back to HEAD with `git diff --stat`. Capture as `docs/standards/evidence.md` form 1: `cmd > <scratchpad>/mut-<n>-<k>.out 2>&1; rc=$?`. The verdict is the exit code (form 6): `rc=0` means the mutant survived, non-zero means it was killed. Never decide from the words in the output.
3. For each corpus row, run the three commands the lists file names for it on the row's input: the oracle, the head's guard and, for a differential, `main`'s guard (`git show origin/main:<path>` into the copy). If the file names no command for a row, report that row as unrun rather than guessing one. Record the three verdicts.
4. Return, and nothing else: one table row per mutant (id, the edit in one line, rc, killed or survived), the list of survivors with the exit code and the last five lines of output for each, the corpus size, the count of rows where the head disagrees with the oracle, the differential's raw count and residual if one was asked for, and the path of every output file. Do not paste test logs or file contents.

A positive control comes with it: run the unmutated copy once first and report its rc, which must be 0; a table whose baseline is red is a failed run, not a clean one.

## 5. The report line

The lane report's `Mutation:` field takes `none owed (no guard)` where the diff adds no guard, and otherwise this form:

```
Mutation: none owed (no guard) | grammar from <spec or schema>, axes <list>; criteria from <plan comment, issue invariants>;
          corpus <n> inputs, oracle <interpreter | library | fixture> | none owed (no exclusion guard);
          mutants <killed>/<total>, equivalent <n>: <the second shape each>; unkillable <n>: <guard — reason each>;
          declared <n>: <issue each>
          differential none owed (no prior version on main) | <rows> rows from list (a), head-regressions (main matches the oracle, head does not)
          <raw> raw, <residual> after <named divergence — where it lives, fixed vocabulary by commit | none>
```
