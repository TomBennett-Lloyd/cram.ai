# eval

The synthetic evaluation course: its deck, golden questions, two sets of hand labels and its golden topics. What each is for, and the categories the deck must hold, are `docs/adr/0005-evaluation-as-gate.md` § Decision (a)–(c)'s.

- `eval/decks/hollowmere/` — the deck, one JSON file per lecture, parsed by `DeckLecture` (`eval/src/deck.ts`). The subject is a fictional guild's beekeeping course, self-written for this repository, which deliberately teaches things a general model believes false about bees: the subject class `docs/adr/0001-grounding-architecture.md` § Context names.
- `eval/questions.jsonl` — the golden questions, one `GoldenQuestion` per line (`eval/src/golden-question.ts`, which also exports `inContradictionSet` and `firstForbiddenEntry`). A line may carry `misspelt` variants, which are retrieved and never asked (`docs/adr/0010-misspelt-golden-variants.md` § Decision (a)).
- `eval/labels/verifier.jsonl` — the verifier hand labels, one `HandLabel` per line (`eval/src/hand-label.ts`).
- `eval/labels/sentence-kind.jsonl` — the sentence-kind sample of `docs/adr/0009-explanation-answers.md` § Decision (o), one `SentenceKindLabel` per line (`eval/src/sentence-kind-label.ts`): a sentence, the slides it is judged against, and whether it is a course claim or an interpretation.
- `eval/labels/topics.jsonl` — the golden topics, one `TopicLabel` per line (`eval/src/topic-label.ts`): a slide and the topics a student would look for it by, one of them the topic of an example a slide about another topic uses (#426).

`auditEvalCourse` (`eval/src/audit.ts`) checks the five against each other, and `eval/src/eval-course.test.ts` runs it over the committed files under `pnpm test`.

`renderDeckPdfs` (`eval/src/render-deck.ts`) renders the deck to one PDF per lecture at test time, into a directory outside the checkout, for the ingest path: an `imageOnly` slide becomes a single image with no text layer. `eval/src/render-deck.test.ts` reads every rendering back through `@cram/ingest`'s `ingestPdf`. No rendering is tracked.

## The runner and its report

`runEval` (`eval/src/run-eval.ts`) runs the whole pipeline over a course through any `ModelGateway` and returns an `EvalReport` (`eval/src/report.ts`), the report `docs/adr/0005-evaluation-as-gate.md` § Decision (f) describes. It first tags every chunk with its topics and summarises each lecture into the index, as ingest does (`IndexRetriever.tag`, #426; `IndexRetriever.summarise`, `docs/adr/0009-explanation-answers.md` § Decision (l)), and reports `tagRecall` over the golden topics (`eval/src/tag-recall.ts`) and `summaryYield` and `summaryUnitYield` (`eval/src/summary-rows.ts`). It then asks every golden question at both depths of `docs/adr/0009-explanation-answers.md` § Decision (o), over one retrieved set and the stored summaries of its slides' lectures (`IndexRetriever.summariesFor`): Ask's light depth, each sentence attributed through the open index (`eval/src/ask-depths.ts`), and the revision guide's deep depth under each of `DEEP_STRATEGIES` in `eval/src/run-eval.ts`, whose contradiction set is the gate. `assembleContext` (`packages/grounding/src/assemble-context.ts`) fits each prompt to the prompt budget, and `contextOverflow`, `sourceCoverage` and `promptTokens` (`eval/src/context-rows.ts`) report what it held and left out. `attribution` and `deepPairs` (`eval/src/depth-rows.ts`) count the cross-encoder pairs the chat mark and the deep verdict sent, the deep ones per answer (#439). It also runs the deep depth's sentence-kind judge (`classifySentenceKinds`, `packages/grounding/src/classify-sentence-kinds.ts`) over the labelled sample, one call per sentence. Which depth each surface runs at is `VERIFICATION_DEPTH`'s. `generatorCutOffs` (`eval/src/timed-gateway.ts`) records the generator's `maxOutputTokens` and counts the replies it or the timeout cut off, out of `latency.perCall.generator.samples` calls, reported and never gated (#578). `RecordingGateway` (`eval/src/recording-gateway.ts`) records a run's model calls in the form `FakeGateway` replays. `eval/src/run-eval.test.ts` records one run and replays it to the same report.

## The live run

`pnpm eval` is tier 2 (`docs/adr/0005-evaluation-as-gate.md` § Decision (e)), and its entry is `eval/src/live-run.measure.test.ts`, whose header names the environment it reads. It runs `runEval` over the course as ingest makes it (`ingestedCourse`, `eval/src/ingested-course.ts`), through the backends `liveConfig` (`eval/src/live-config.ts`) configures and `openLiveGateway` (`eval/src/live-gateway.ts`) opens, and refuses to run unless `measuredCommit` (`eval/src/measured-commit.ts`) finds the tree at `HEAD`.

`eval/src/summary-key.measure.test.ts` runs the summary stage alone, under `CRAM_SUMMARY_KEY=1` and the same backend variables, and prints each lecture's yields, how many citations resolved by number and by copied line, and how many units' text is a slide line verbatim (#481). It writes nothing and runs on a dirty tree, naming the tree's state in its output.

`writeRun` (`eval/src/run-files.ts`) writes the report to `eval/reports/<short-sha>.json` and the run's recordings to `eval/recordings/<short-sha>.jsonl`.

Tier 1 is `eval/src/committed-run.test.ts`: under `pnpm test` it replays the committed recordings through `replayRun` (`eval/src/replay-run.ts`) and expects the committed report back, less wall-clock time (`untimed`). A recording miss fails it, so a change to a prompt, a pin or the sampling owes a new `pnpm eval` run. Its failure names its kind (`TierOneMismatch`, `eval/src/tier-one-mismatch.ts`): `report key absent` or `report key retired` when the committed report no longer fits `EvalReport`, `report invalid` for any other schema issue, `recording miss` with the role that missed, and `value moved` with the path and both values. A lane whose change makes this test red by design, until its tier-2 run re-records it, declares it in the form `.claude/agents/ticket-agent.md` rule 4 states.
